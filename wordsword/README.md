# Wordsword — English B2 → C1

Мобильное PWA для 30-дневного интенсива B2 → C1. В приложении 18 блоков грамматики с теорией, тренировками (Learning Mode) и контрольными (Exam Mode), словари General 200, Business 100, Irregular 120 и AI Agents 123, Case Lab (182 задания в 6 форматах), Theory Check, смешанный экзамен, карта причин ошибок, Dashboard и экспорт CSV/JSON. После первого открытия всё работает без интернета. Прогресс хранится на устройстве (IndexedDB) и никуда не отправляется.

## Быстрый старт на компьютере
Распакуйте архив и откройте `wordsword/index.html` двойным щелчком: приложение запускается прямо с диска (проверено в Chrome). Установка и офлайн-режим при открытии с диска недоступны — для них нужен HTTPS (см. ниже).

## Установка на телефон через GitHub Pages
1. В репозитории удалите старые файлы приложения, если они там есть.
2. **Add file → Upload files** → перетащите **всё содержимое** папки `wordsword`: `index.html`, `app.bundle.js`, `sw.js`, `manifest.webmanifest`, файл `.nojekyll` и папки `lib`, `css`, `icons`. Папки `src`, `tests`, `tools`, `docs` и файл `package.json` — это исходники, для работы они не нужны, но и не мешают.
3. **Файл `.nojekyll` обязателен.** Без него GitHub Pages публикует сайт через Jekyll, а тот может пропустить служебные файлы. В прошлой версии именно из-за этого не загружалась папка `vendor/` и экран зависал на «Загрузка…». Если файл с точкой в начале имени не загружается перетаскиванием, создайте его вручную: **Add file → Create new file**, имя `.nojekyll`, содержимое пустое, **Commit**.
4. **Settings → Pages → Deploy from a branch → `main` / root.**
5. Через 1–2 минуты откройте `https://<имя>.github.io/<репозиторий>/`.

Если на хостинг попали не все файлы, вместо бесконечной «Загрузки» появится сообщение, какого файла не хватает.

### Android (Chrome)
⋮ → «Установить приложение» (или «Добавить на главный экран»).

### iPhone (Safari)
«Поделиться» → «На экран „Домой“». Учтите, что у иконки на iPhone отдельное хранилище: прогресс в Safari и в установленном приложении не общий.

Если раньше по этому адресу была открыта сломанная версия, один раз обновите страницу (на телефоне закройте вкладку и откройте снова).

## Обновление
Замените файлы на хостинге. Если меняли исходники в `src/`, сначала пересоберите проект:
```
npm i -D esbuild fake-indexeddb
ESBUILD=node_modules/.bin/esbuild node tools/build.mjs
```
Скрипт соберёт `app.bundle.js` и `sw.js` с новой версией кэша. Обновление **не стирает прогресс**.

## Сохранность данных
- Каждое действие сохраняется сразу; в шапке «Сегодня» показан индикатор «Сохранено ЧЧ:ММ:СС».
- Незавершённые контрольные продолжаются после закрытия и перезагрузки.
- Приложение запрашивает постоянное хранилище, но браузер не гарантирует сохранность: данные пропадут, если очистить данные сайта, удалить приложение или если ОС освободит место. Регулярно делайте резервную копию: **Прогресс → Резервная копия JSON**. Импорт сначала проверяет файл и просит подтвердить замену данных.
- Прогресс старого vocab-app переносится автоматически, если новое приложение открыто по тому же адресу.

## Экспорт CSV
**Прогресс → Экспорт CSV** (за выбранный период) или **Полный CSV**. Создаются 4 файла: `weekly_summary`, `test_attempts`, `answer_events`, `error_map` (UTF-8 с BOM, даты ISO 8601). Где браузер поддерживает отправку файлов через меню «Поделиться», откроется оно (на iPhone — «Сохранить в Файлы»); иначе файлы скачаются в «Загрузки».

## Для разработчика
```
node tools/validate.mjs                      # проверка контента + отчёт покрытия
node --test tests/*.test.mjs                 # unit-тесты (нужен fake-indexeddb)
python3 tests/e2e/e2e_main.py                # браузерные сценарии (pip install playwright)
python3 tests/e2e/e2e_offline.py
python3 tests/e2e/e2e_cases_theory.py
```
Архитектура и схемы данных описаны в `docs/ARCHITECTURE.md`, отчёт о проверках — в `docs/REPORT.md`.
